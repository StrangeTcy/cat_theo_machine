1. Test A — compare_search_modes_finds_reusable_worker_snapshot_dir_test
   (testsuite.py:8716)

contract under test: a checkpoint written by _search_worker_checkpoint
into <root>/snapshots/search_compare/run-1/bfs.snapshot.json must be
found by _reusable_search_worker_result_paths(root) as the mapping
"SearchBFS" -> that exact path, while a sibling run-2 whose result
manifest carries wrong problem texts is not adopted.

executed path:
  test -> _write_search_worker_manifest (search/compare_subprocess.py:24,
  writes start_text/goal_text beside the snapshot) ->
  _search_worker_checkpoint (main.py; snapshot codec writes roots
  including worker_plan, worker_stage, search_history) ->
  _reusable_search_worker_result_paths (search/compare_subprocess.py:338)
  -> result_root resolves correctly, run-1 enumerated, bfs.snapshot.json
  exists -> _search_worker_snapshot_matches_current_problem
  (search/compare_subprocess.py:319)

failing assertion: "SearchBFS" not in found — found is the empty
  mapping. The mismatching sibling is (correctly) not adopted; the
  MATCHING checkpoint is also dropped.

failure mechanism, pinned by direct instrumentation of each gate:
  (a) PRIMARY — identity-only equality at the match gate.
      _search_worker_snapshot_matches_current_problem rejects on
      M.TermEqual(SearchAttemptStart(attempt)(), self.start). The
      attempt comes back from the snapshot codec with freshly minted
      term identities. TermEqual (matching.py:41) is object-identity
      at the leaves: constructor labels compare by IdentityCompare and
      literal payloads are never value-compared. Demonstrated in the
      smallest form: two freshly constructed in-memory Char terms
      carrying the same symbol are NOT TermEqual to each other — only
      the identical object passes. Therefore ANY start/goal containing
      a literal (Char here) can never match after a codec round-trip,
      even when the same objects were checkpointed. The singleton
      EmptyList tail does survive (same object), which is why the
      heuristic axis (labels + numeric fields) round-trips equal while
      the Char axis cannot. Cross-process reuse as written is
      unreachable for every real problem.
  (b) SECONDARY, independent — heuristic axis mismatch. Even with a
      value-level start/goal compare, the scan matches against
      self._heuristic_for_mode(mode) (search/compare_attempts.py:324),
      built from THIS probe's heuristic fields, while the test's
      checkpoint stores the worker heuristic
      _search_worker_mode_heuristic (main.py:521) built from the fresh
      runtime's theorem_heuristic — different rule-order/beam fields;
      measured NOT TermEqual. Two independent rejections, either of
      which alone yields the empty mapping.

what already works (all instrumented green; reproduced by probe 0):
  checkpoint write; scan enumeration and run ordering; mode-token path
  assembly (_mode_worker_token); _loaded_worker_attempt_is_final logic;
  _partial_worker_attempt_is_resume_ready returns truth with a
  non-empty worker_plan root loaded from the written checkpoint;
  resume-stage ranking.

remedy requirement (corrected 2026-09-08; supersedes the original
  report's suggestion that the manifest mechanism could serve as the
  compare):

  Cross-process comparison needs stable value semantics for the supported
  term family, or a canonical, constructor-kind-preserving encoding.

  Debug rendering is diagnostic output, not proof of identity.
  Matching start/goal values is necessary but does not establish snapshot
  compatibility or validate a returned proof.

  probe 1 confirms the collapse empirically at this base:
  _write_search_worker_manifest renders through _debug_term, and
  DebugTerm (proof.py:141) returns the empty string whenever
  DEBUG_TRACE_STATE is false — its default. Two probes with different
  goals both wrote start_text "" and goal_text ""; the manifest cannot
  distinguish the problems, let alone validate a returned proof.

  Heuristic compatibility remains a separate check. Do not remove it
  merely because start/goal comparison was repaired.

locus of the defect seam: search/compare_subprocess.py:319-331 (match
  gate) with the equality primitive at matching.py:41-80 (leaf
  IdentityCompare) — or, equivalently, an identity-preserving codec;
  which side is the right repair is a ruling for INT / Agents B-C, not
  this lane.

2. Test B — compare_search_modes_fill_warms_resident_pool_before_root_wave_test
   (testsuite.py:9121)

contract under test: with parallelism one, _fill_parallel_workers over
  freshly built comparison states must (1) have spawned > 0, (2) leave
  _comparison_shared_root_candidates_ready truth, (3) return a
  non-empty worker chain, (4) leave next states not needing a shared
  root wave. The intent: warm the resident pool BEFORE the root wave
  materializes.

executed path:
  test -> _comparison_states(_mode_chain()) (search/compare_state.py:395;
  each state via _comparison_state with phase unset -> defaults to
  SearchRootFastPathPhaseLabel, search/compare_state.py:33) ->
  _fill_parallel_workers (search/compare_executors.py:656)

failing assertion: exactly ONE of the four checks fails — (2)
  _comparison_shared_root_candidates_ready is false after the fill.
  Checks (1), (3), (4) pass: spawned is nonzero (the normal leasing
  path _collect_parallel_worker_launches spawns; the warm branch did
  not), workers chain non-empty, next states still do not request a
  wave.

failure mechanism, pinned per state (all five modes measured
  identically, reproduced by probe 0): _comparison_states_need_shared_
  root_wave (search/compare_packets.py:1417) requires a state that is
  Running AND in SearchPacketSearchPhaseLabel AND zero active packets
  AND empty pending AND a fresh-root job. Fresh states satisfy every
  conjunct EXCEPT phase: they come up in
  SearchRootFastPathPhaseLabel. So need-wave is false on entry;
  _fill_parallel_workers then (i) skips _grow_parallel_executor_pool's
  warm branch and (ii) _comparison_prepare_shared_root_wave returns
  the states unchanged — _comparison_apply_shared_root_wave never
  runs, and only it sets _comparison_shared_root_candidates_ready
  (search/compare_packets.py:1410 via _comparison_cache_shared_root_
  candidates; initialized false at search/compare.py:69).

classification (corrected 2026-09-08 after operator review; the
  original report's "gating/ordering contradiction, chicken-and-egg,
  unreachable by construction" claim is WITHDRAWN):

  Direct-call fixture/precondition mismatch:
    fresh states passed straight to fill do not establish shared-root readiness.

  Whole scheduler unreachable by construction:
    NOT established by this reproduction.

  The production shared-root entry path (search/compare.py, resident
  path of _compare_all_modes) performs: create fresh states -> start
  and grow the executor pool (pre-fast-path grow at compare.py:213) ->
  evaluate root fast paths (_comparison_states_after_root_fast_paths,
  compare_rules.py:237; on a miss _comparison_root_fast_path_state
  sets the phase to packet search for every running state, BEFORE the
  later fill) -> enter the fill loop (compare.py:265). The transition
  is therefore not confined to the wave whose preparation the warm
  precedes.

  probe 2 measured both entries at this base (all parts on isolated
  fixtures with the suite's fake executor probes, no real processes):
    A. direct entry (the red test's order), miss-capable ruleset:
       need-wave false before and after the fill;

    C. the red test's own ruleset under the production order: fast-path

  Do not change the initializer, broaden the predicate, or enable the

3. Isolation boundary: rejection mutates the parent (new 2026-09-08)

At this base _search_worker_snapshot_matches_current_problem calls
_load_search_worker_snapshot BEFORE the compatibility compares
(search/compare_subprocess.py:319-321), and the loader merges the
decoded constructor registry into the parent and replaces the parent
graph's constructor context (self.registry = self._merge_tree(...);
self.graph._replace_context(constructors=self.registry)) — a
subsequently rejected candidate has therefore already reached a
parent-write path.

probe 3 (a real checkpoint written from a distinct second runtime for
a DIFFERENT problem — start and goal both differ; the matcher rejects
it; identity checks on the parent's active state):

  matcher accepted the foreign problem:       false
  parent registry unchanged after rejection:  false
  parent graph context unchanged:             false

VERDICT: a rejection leaves the parent MUTATED at this base. This
confirms the operator's source inspection empirically; it is a
boundary finding, not a reproduced corruption scenario.

Required ordering for Agents B/C:

  decode privately
  → validate task, snapshot and configuration compatibility
  → replay the claimed result
  → commit only the accepted effects

A rejection must leave the parent's active state unchanged.

HALF-BUILT FRONTIER — not a dead experiment (unchanged). All
surrounding machinery exists and is internally coherent: the
checkpoint/resume pipeline end-to-end minus its match gate's equality
primitive; the resident executor pool, packet queues, root-wave fanout
and retry/replace paths (their sibling tests pass at baseline — only
these two are red). Three named seams, each narrow:

  seam 1 (cross-process resume): the match gate needs stable value
    semantics for the supported term family or a canonical,
    constructor-kind-preserving encoding. Debug/manifest text is NOT
    an identity key (probe 1: empty renders with tracing off). Heuristic
    compatibility is a separate check that must survive any start/goal
    repair. Candidate repair 327a263 demonstrates the M.Compare
    direction on both axes.
  seam 2 (warm-before-wave): NOT a proven circular dependency. The
    production order reaches the warm branch (probe 2B); the red test's
    direct-call entry does not (probe 2A). The open question is
    entry/fixture coverage, now parked by INT's REVIVE-LATER ruling
    pending CONVERGE.
  seam 3 (rejection isolation): decode-then-validate ordering is
    required (section 3) — a rejection must leave the parent's active
    state unchanged; at this base it does not.

No re-implementation is warranted; nothing here justifies replacing
the partial machinery. Agent B's two-class journal and Agent C's
serial admission must treat TermEqual's identity semantics as a hard
boundary: only labels and structurally-shared singletons survive
reconstruction — evidence-class mergeability across processes requires
stable value semantics or a canonical encoding, exactly the lesson of
seam 1, and the decode-privately ordering of seam 3 is the isolation
contract for any cross-process acceptance.
